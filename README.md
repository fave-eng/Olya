# Olya's English Space — новая структура

Сайт Оли перестроен по архитектуре сайта Марины:

- общий интерфейс: `app.js` и `styles.css`;
- домашние работы: `data/lessons/lesson-*.json`;
- словари: `data/vocabulary-data.js`;
- грамматика: `data/grammar-data.js`;
- общий Supabase-проект: `zqzgarvmpqqqaobeicpc`;
- отдельный идентификатор ученицы: `olya`.

В новый формат перенесены четыре домашние работы, три словарные темы и пять грамматических тем.

## Как перенести прогресс без потерь

Используются два независимых механизма.

### 1. Перенос данных из старого Supabase

Этот шаг лучше выполнить **до публикации нового сайта**.

1. В SQL Editor общего проекта `zqzgarvmpqqqaobeicpc` выполните `supabase/shared-progress-schema.sql`, только если таблицы прогресса ещё не подготовлены для текущей версии сайта Марины.
2. В репозитории Оли откройте **Settings → Secrets and variables → Actions** и создайте секреты:
   - `OLD_SUPABASE_SERVICE_ROLE_KEY` — service-role key старого проекта `echffgdxkcxvobrwwiyw`;
   - `NEW_SUPABASE_SERVICE_ROLE_KEY` — service-role key общего проекта `zqzgarvmpqqqaobeicpc`.
3. Откройте **Actions → 0 - Migrate Olya progress to shared Supabase → Run workflow**.
4. Проверьте, что workflow завершился без ошибки.

Скрипт переносит:

- результаты Homework 1–4;
- точные известные слова из `vocab_progress`;
- известные неправильные глаголы из `irreg_progress`;
- итоговые старые счётчики словаря.

Повторный запуск не стирает ответы, появившиеся уже на новом сайте, и не заменяет существующие записи словаря.

### 2. Автоматический перенос localStorage

После загрузки новой версии на тот же адрес GitHub Pages сайт при первом открытии сам прочитает старые ключи браузера:

- `olya_hw1_*`, `olya_hw2_*`, `olya_hw3_*`, `olya_hw_hw4`;
- `olya_vocab_unit2a-nouns`, `olya_vocab_unit2a-verbs`, `olya_vocab_holidays`;
- `olya_irreg_known`.

Старые ответы, баллы и отметки словаря преобразуются в новый формат и синхронизируются с общим Supabase. Этот механизм работает только в том браузере и на том устройстве, где сохранился старый `localStorage`, поэтому облачную миграцию всё равно нужно выполнить.

## Правило словаря

В новой версии просмотр карточки не делает слово выученным. Статус `known` появляется только после правильного ответа в полностью завершённом тесте.

Старые отметки импортируются как исторический прогресс, чтобы уже сохранённые результаты не пропали. Все новые действия работают по новому правилу.

## Публикация

Замените содержимое репозитория Оли файлами из этого архива, сохранив структуру папок. После публикации откройте сайт в том браузере, которым Оля пользовалась раньше, и дождитесь синхронизации с Supabase.

## Telegram

Старая версия страниц содержала Telegram bot token прямо в HTML. В новой версии токена и chat ID в клиентском коде нет. Старый токен необходимо перевыпустить через BotFather, поскольку он остаётся раскрытым в старой истории Git.

Для уведомлений используйте workflows `1-setup-telegram.yml` и `2-notify-new-materials.yml`, задав `SUPABASE_PROJECT_ID=zqzgarvmpqqqaobeicpc` и отдельного получателя для `student_id=olya`.

## Ограничение безопасности

Сайт повторяет текущую архитектуру Марины без входа пользователя. Данные Марины и Оли разделяются полем `student_id`, но строгая изоляция между посетителями требует Supabase Auth и более жёстких RLS-политик.
